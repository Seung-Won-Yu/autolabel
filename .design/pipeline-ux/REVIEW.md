# 전체 파이프라인 사후 감사

## 결론

개인용 프로토타입 수준에서 도메인 라벨링 도구로 넘어갈 때 위험했던 경계는
`학습 데이터 승인 상태`, `학습 워커 실행 위치`, `평가 분할`, `체크포인트의 실제
운영 가능성`, `통계 표본과 화면 목록의 일치`였다. 이번 개발에서 다섯 경계를
코드와 회귀 테스트로 잠갔다.

## 해결한 고위험 항목

| 심각도 | 발견 | 조치 | 검증 |
|---|---|---|---|
| Critical | 외부 데이터 루트에서 학습 워커가 `server`를 import하지 못함 | 코드 루트와 데이터 루트를 분리 | 격리 루트 실제 학습 완료 |
| Critical | 일반 YOLO zip이 리뷰 전 데이터 포함, train=val | 승인 전용 고정 train/val/test 패키지 추가 | zip 내용 API 테스트 + 종단 QA |
| Critical | mAP가 높은 epoch 2 best가 기본 conf에서 검출 0건 | best/last 운영 F1 비교, 모델별 임계값 저장 | 새 20장 17장 검출 |
| High | 배치 검수 중 표본 아닌 이미지도 목록에 보임 | 표본 목록 잠금, 장별 정상/오류 판정 | Playwright 사용자 흐름 |
| High | 390px에서 176px 가로 넘침, 캔버스가 화면 밖 | 작업대 우선 반응형 레이아웃 | 390px overflow 0, canvas 378px |
| Medium | 한국어 앱인데 문서 언어·제목이 기본값 | `lang=ko`, 제품 제목·설명 | 렌더 감사 |
| Medium | 도움말·토스트·목록의 키보드/상태 전달 부족 | dialog 포커스 트랩, live region, focus-visible, 목록 키보드 | lint/build/Playwright |
| Medium | 클래스 편집이 키 입력마다 PUT되고 실패가 안 보임 | 직렬화된 debounce 저장 + 명시적 상태/재시도 | lint/build |

## 남은 의도적 한계

- Colab 세션 자체는 앱이 제어하지 않는다. zip과 노트북을 내려받고 `best.pt`를
  다시 등록하는 수동 경계는 유지한다.
- 일반 COCO/YOLO zip은 전달·백업용이라 거부 데이터만 제외한다. 학습에는 반드시
  화면의 `승인 학습 데이터.zip`을 써야 하며 UI에서 두 목적을 구분했다.
- 모바일은 빠른 검수와 상태 확인이 목표다. 정밀 박스 편집은 데스크톱/태블릿이
  주 사용 환경이다.
