# autolabel

**프롬프트 한 줄에서 전용 모델까지 — 로컬에서 돌아가는 오토라벨링 도구**

객체를 *말하거나 · 예시로 그리거나 · 클릭*하면 자동 라벨링하고,
승인 라벨이 쌓이면 **알아서 전용 모델을 학습**해 다음 라벨링부터 그 모델이 일한다.

클라우드 없음 · API 키 없음 · 데이터 유출 없음 — Apple Silicon 한 대로 전 과정 완결.

## 무엇이 다른가

기존 라벨링 도구는 "사람이 그리는 화면"이고, 오토라벨은 부가 기능이다.
이 도구는 반대로 **모델이 먼저 다 깔고, 사람은 틀린 것만 고치는 흐름**을 1급 시민으로 만들었다.

```
 ┌──────────────────────────────────────────────────────────────┐
 │  텍스트 프롬프트  ·  예시 박스 1개  ·  SAM 클릭              │
 └───────────────────────────┬──────────────────────────────────┘
                             ▼
                    자동 라벨 (배치/단건)
                             ▼
          리뷰 큐  ─ 불확실 우선 / 의심 우선 정렬
                             ▼
              승인 8장 → 전용 모델 자동 학습
                             ▼
        게이트 통과 시 오토라벨 엔진 교체 ──┐
                             ▲             │
                             └─────────────┘
                       라벨링할수록 라벨링이 쉬워진다
```

## 실측 성능

| 항목 | 수치 |
|---|---|
| 배치 오토라벨 (M4 Pro, MPS) | 장당 **0.8초**(박스) / 1.8초(박스+마스크) |
| SAM 클릭 보정 | 임베딩 1.4초/장(1회, 캐시) + 클릭당 **~120ms** (브라우저 실행) |
| 흔한 객체 제로샷 (person) | GT 기준 **mAP50 0.906** |
| **콜드스타트 구출** — PCB 결함, 제로샷이 완전 실패하는 도메인 | 제로샷 **≈0** → 승인 30장 **0.472** → 승인 42장 **0.593**<br>(홀드아웃 10장 고정 기준, 검출 3 → 43 → 64개 / GT 81개) |
| 예시 찾기 | 리모컨 1개를 예시로 → 나머지 전부 검출, 오탐 0 |
| **프롬프트 실험** (signature, 정답 대조) | 프롬프트만 바꿔 제로샷 회수율 **4/9 → 8/9**, 오탐 13 → 9<br>(`handwritten signature` → `autograph`. 박스 수 1위였던 `signature`는 오탐 33로 과검출 — 실험이 이걸 걸러냈다) |
| **문서 서명 검출** (143장 연결 임포트) | 제로샷 15장에 3개 → 시드 100장 자동 학습 → 홀드아웃 43장 **mAP50 0.969** |
| 라벨 심판 (공공 데이터 검증) | signature 120장 · mAP50 0.995 모델 기준 **추정 오류율 0.0%**, 박스 어긋남 1건만 별도 표시<br>(초기 1.7%는 전량 오탐이었다 — 같은 객체를 다르게 잡은 것을 '누락'으로 세던 결함, 아래 참조) |
| champion/challenger 게이트 | 60장 challenger가 val 열세로 **승격 거부** — 나쁜 재학습 방어 실작동 |

> 핵심 결론: **흔한 객체는 첫날부터 자동, 특수 도메인은 수동 수십 장 투자 후 자동.**

## 기능

**라벨링**
- 텍스트 프롬프트 배치 오토라벨 (클래스별 프롬프트·임계값 분리)
- 예시 박스 1개 → 유사 객체 전부 (PerSAM 방식 특징 매칭, 학습 불필요)
- SAM 클릭 → 마스크 (클릭=새 객체, Shift=정제, 우클릭=제외)
- 박스 드래그·이동·리사이즈, 휠 줌 / Alt 팬

**리뷰**
- 썸네일 리스트 + 상태·라벨수·신뢰도·QA 점수
- 필터 4종 · **불확실 우선** · **의심 우선** 정렬 — `←→` 이동도 이 순서를 따름
- `A`/`X` 승인·거부 후 자동 다음, `1~9` 클래스 재할당
- **`Cmd+Z`가 이미지를 건너서도 되돌린다** — 오승인도 취소된다. 그 이미지로 자동 복귀 (100단계)
- 우측 어노테이션 패널 — 선택·클래스 변경·삭제, 출처 표시(🤖 모델 / ✍️ 사람 / ▦ 마스크)
- **이미지 목록 상시 노출** — 설정·도구(클래스·임포트·익스포트·학습)는 접히고, 매번 쓰는 썸네일 목록이 사이드바를 차지한다
- 넘길 때 목록이 따라오고 `26 / 143` 위치 표시 · **Shift/⌘+클릭 다중 선택 → 일괄 승인·거부**
- 서버 썸네일(디스크 캐시) — 목록이 원본을 받지 않는다 (**전송량 −97.8%**)
- **창 렌더링** — 보이는 구간만 DOM에 올린다 (310장에서 노드 2364 → 321)
- 박스 선택 중 화살표로 **1px 미세조정**(Shift 10px), `Esc` 선택 해제
- 거부 이미지는 **익스포트에서 제외**되고 `거부` 필터로 되살릴 수 있다
- 배율 표시 + 맞춤 버튼, `+`/`−`/`0` · 캔버스가 창 크기를 따라간다
- **2초 자동 저장 + 실패 시 경고·자동 재시도** — 저장이 안 되면 헤더에 계속 표시하고 5초마다 재시도, 서버가 돌아오면 스스로 복구. 미저장 상태로 창을 닫으면 경고
- 드래그앤드롭 업로드 · "지금 할 일" 단계 안내 배너
- **비디오 임포트** — mp4/mov를 올리면 프레임 추출(간격 선택) + SAM 3 메모리
  전파 트래킹으로 프레임별 초안 라벨 자동 생성. 같은 객체는 `meta.track_id`로
  연결. 영상 데이터는 라벨 비용이 "전 프레임 그리기"에서 "검수"로 줄어든다
- QA 권장 임계값 **원클릭 적용** · 전용 모델 `.pt` 다운로드
- 익스포트는 **바로 학습 가능한 zip** (YOLO: images/ + labels/ + data.yaml)

**콜드스타트 (제로샷이 약할 때)**
- **프롬프트 실험** — 후보 표현을 표본 5장에 돌려 검출 장수·확신도·장당 박스로 비교하고, 이긴 것을 클릭 한 번에 적용. 제로샷 품질은 프롬프트가 좌우하는데 예전엔 전체를 다시 돌려보는 것 말고 비교할 방법이 없었다
- **배치 결과 진단** — 검출률이 낮으면 결과만 던지지 않고 다음 수를 지정한다 (프롬프트 실험 / 직접 라벨 후 학습)

**자동화 (리뷰 부하 감소)**
- **문맥 심판 (VLM)** — 외형만으로 판정할 수 없는 라벨용 (예: "사고에 연루된
  차량만"). 판정 기준을 글로 쓰면 VLM이 박스마다 부합✓/위반✗/불확실? + 근거를
  달아준다 — 사람은 위반·불확실만 확인한다. 검출 모델은 "어디 있나"만 알고
  "기준에 맞나"는 문맥 판정이라, 기준 텍스트를 읽는 VLM만 자동 제안이 가능한
  부류다. 제공자는 플러그인 — Claude API(빠름, 종량 과금) / **Claude Code CLI
  헤드리스(구독에 포함, 추가 비용 없음 — API 키 없이 쓰는 기본 경로)** / 로컬
  Ollama, 없으면 기능만 비활성. 같은 기준 재실행은 캐시를 써서 비용 0.
  판정은 병렬(기본 3워커, `AUTOLABEL_VLM_WORKERS` — Ollama는 1), 한 변 24px
  미만 초소형 박스는 호출 없이 "불확실·직접 확인"으로 확정해 시간·비용 절감
- **고신뢰 자동 승인(TBAL)** — 모든 박스가 임계값 이상인 이미지를 한 번에 승인, 승인 전 미리보기(대상 수·커버리지). 사람은 저신뢰만 본다
- **누락 찾기** — 모델이 찾았는데 라벨에 없는 박스를 점선으로 제안, 클릭 한 번에 라벨로 승격 (공공 데이터 라벨 세탁)
- **다음 라벨 추천** — 모델이 헷갈리는 이미지를 우선 제시 (능동학습, 라벨 예산 최적화)
- **학습 이력** — 라운드별 mAP 막대 + 이전 모델로 롤백

**계층 라벨 (객체 안의 객체)**
- 클래스를 `person.head`처럼 쓰면 **part 캐스케이드** 작동 — 부모를 먼저 찾고 그 crop 안에서만 부위를 검출
- 사람 부위는 키포인트 전문 모델 경로 (머리·팔·다리·몸통), 일반 객체는 crop 확대 후 grounding
- part는 `parent_annotation_id`로 부모와 연결되어 저장

**학습 & 품질**
- 승인 8장부터 자동 파인튜닝, 이후 5장마다 재학습 (별도 프로세스 — 서버 재시작에도 생존)
- **데이터 규모별 모델 자동 승급**: ~150장 yolo11n · ~800장 yolo11s · 그 이상 yolo11m
- **☁ Colab 학습**: 로컬로 감당 안 되는 규모는 노트북을 받아 GPU에서 학습 → `.pt`를 다시 등록
- 고정 골드 val 스냅샷 → 라운드 간 동일 기준 게이트
- 클래스별 추천 임계값 (정밀도 95% 달성 최소 confidence)
- 라벨 의심 랭킹 (모델 vs 라벨 불일치, 확신도 가중)
- COCO / YOLO 익스포트, 라벨 출처 메타데이터(모델명·프롬프트·임계값) 기록

## 스택

```
webapp/   Vite + React + react-konva
          └ SAM 디코더 ONNX(16.5MB)를 브라우저에서 실행 → 클릭당 서버비용 0

server/   FastAPI + SQLite
          ├ Grounding DINO   텍스트 → 박스
          ├ SAM 3 (선택)      텍스트 개념 → 모든 인스턴스 분할 (models/sam3.pt 있으면 자동)
          ├ SAM ViT-L        박스 → 마스크, 임베딩, 예시 매칭
          ├ YOLO11n          전용 모델 (자동 파인튜닝, MPS)
          └ 엔진 라우팅       활성 전용 모델 > SAM 3 > GDINO+SAM 폴백
```

## 실행

```bash
./setup.sh     # 최초 1회: venv + 의존성 + SAM 가중치(1.2GB) + 브라우저 디코더
./start.sh     # 백엔드 + 프론트 동시 실행, 브라우저 자동 오픈 (종료: Ctrl+C)
./test.sh      # 백엔드 회귀 (1초) — 코드를 고쳤으면 항상 실행
./test-e2e.sh  # 프론트 회귀 (Playwright, 10초) — 서버는 격리 DB로 자동 기동
```

Grounding DINO · YOLO11n은 첫 사용 시 자동 다운로드.

### SAM 3 켜기 (선택)

[facebook/sam3](https://huggingface.co/facebook/sam3)에서 접근 승인 후 `sam3.pt`(3.45GB)를
`models/sam3.pt`로 두면 제로샷 검출이 SAM 3로 자동 승급된다 (재시작 불필요 — 요청마다 확인).
추가 의존성 `timm` + ultralytics CLIP 포크는 requirements.txt에 포함. SAM 3 라이선스는
자체 라이선스(SAM License) — 상용·재배포 조건은 원문 확인.

## 사용 흐름

1. 프로젝트 생성 → 클래스 정의 (이름 / 검출 프롬프트 / 임계값)
2. 이미지 업로드 → **전체 오토라벨**
3. 리뷰: `←→` 이동 · `A` 승인 · `X` 거부 · `Del` 삭제 · `?` 단축키
4. 보정: `B` 박스 · `M` SAM 클릭 · `E` 예시 찾기
5. 승인이 쌓이면 전용 모델이 자동 학습 → 오토라벨 품질 상승
6. `QA 분석` → 추천 임계값 확인 + "의심 우선"으로 라벨 오류 사냥
7. COCO / YOLO 익스포트

## 회귀 테스트

`tests/`의 40개 케이스는 **전부 실제로 한 번씩 깨졌던 경로**다 — 연결 임포트 이미지의
학습 실패, 게이트가 좋은 모델을 거부한 오판, 대량 승인 중 학습 조기 발동,
좌표 변환 오류 등. 모델 추론 없이 1초 안에 돌아 개발 중 매번 실행할 수 있다.

```bash
./test.sh                    # 전체
./test.sh tests/test_core.py # 핵심 로직만
```

커버리지: 3분할·게이트 규칙 · acceptance sampling 수학 · 학습 설정 자동 결정 ·
계층 온톨로지 파싱 · 타일링 NMS · QA 매칭 · **누락 제안 중복 필터** · 프로젝트 CRUD ·
업로드→라벨→익스포트 · 연결 임포트 좌표 변환 · **익스포트 zip 실내용**(파일
시그니처가 아니라 이미지·라벨 개수) · **프로젝트 삭제가 원본을 안 건드림** ·
**모델 임포트·롤백·잘못된 롤백 거부** · 자동 승인 임계값 · 일괄 상태 · Colab 노트북 ·
**연결 이미지 삭제가 원본을 안 건드림** · **배치 기본 대상에서 승인 이미지 제외** ·
**온톨로지에 없는 클래스 익스포트 제외** · **train 분할 고갈 방지** ·
**SAM 추론 직렬화** · **잡 상태 재시작 생존** · 라벨 없는 연결 임포트 중복 방지 ·
**업로드 부분 실패 보고·파일명 정규화** · **없는 id 404 (500 아님)**

실서버에 붙어 도는 종단 시나리오 2종:

```bash
.venv/bin/python scripts/qa_e2e.py        # 27항목 · 실학습 포함 (~20분)
.venv/bin/python scripts/qa_parts_e2e.py  # 15항목 · part 캐스케이드
```

전자는 연결 임포트 → 제로샷 → 자동 파인튜닝 → 전용 모델 오토라벨 → 심판 →
익스포트 전 구간, 후자는 부모→crop→부위 검출과 `parent_annotation_id` 연결이
익스포트까지 살아남는지 본다.

프론트는 `./test-e2e.sh` (Playwright, 25항목)가 포인터 상호작용까지 잠근다 —
드래그 박스 생성→저장, `A` 승인·연타 유실, 되돌리기, 창 렌더링, 줌·맞춤,
중단된 배치·임포트를 완료로 말하지 않는지, 저장 실패 알림·자동 복구,
**늦게 도착한 추론 응답 폐기**, **저장 비행 중 편집 보존**,
한글 프로젝트명 익스포트. 전부 실제로 깨졌던 경로다.

## 설계 원칙 (전부 실사고에서 나온 것)

- **마스크 원본 크기 복원은 브라우저 JS에서** — ONNX 그래프에 맡기면 세로 이미지에서 crop 치수가 뒤집힌다 (실측 IoU 0.18)
- **이미지 전환 시 임베딩 무효화** — 순번 검사 + 크기 검증으로 이전 이미지 임베딩 사용 레이스 차단
- **학습은 인프로세스 금지** — 서브프로세스 + 상태 파일. `--reload`가 학습 스레드를 죽인 사고에서 나온 규칙
- **champion/challenger + 품질 하한선(mAP50 ≥ 0.3)** — 재학습이 항상 개선은 아니다. 콜드스타트 쓰레기 모델의 승격 차단
- **온톨로지 = config** — 클래스명과 검출 프롬프트를 분리 (도메인 전환이 설정 변경으로 끝난다)
- **"정탐이냐"와 "새 객체냐"는 다른 질문** — mAP 관례의 IoU 0.5를 누락 판정에 쓰면
  IoU 0.4로 겹친 같은 객체가 '누락'으로 나가 중복 라벨이 박힌다. 신규 판정은
  IoU + 양방향 포함률로, 훨씬 엄격하게
- **조용한 skip 금지** — 파일이 없으면 건너뛰지 말고 세어서 노출한다
  (`X-Images-Missing`). 빈 익스포트가 성공으로 보이던 사고에서 나온 규칙
- **파괴적 UPDATE 전에 대상 확인** — 없는 id로 롤백하면 전부 비활성화만 되고
  아무것도 활성화되지 않아 전용 모델이 사라졌다
- **검증은 실내용을 봐야 한다** — zip의 `PK` 두 바이트를 확인하는 검사가
  data.yaml 한 장짜리 빈 zip을 통과시켰다. 개수를 세라
- **비동기 핫키는 ref + 큐로** — 승인이 클로저의 `current`를 읽어, 연타하면
  같은 이미지를 두 번 처리하고 나머지를 건너뛰었다 (실측 5연타 → 2장).
  최신 값은 ref로 읽고 작업은 프라미스 체인으로 직렬화한다
- **되돌리기 이력은 이미지가 아니라 프로젝트 단위** — 이미지별로 두면 넘기는
  순간 사라져서, 되돌릴 수 없는 파괴적 동작(오승인)이 생긴다
- **실패한 저장은 반드시 화면에 남긴다** — 자동 저장에 catch가 없어 서버가
  죽으면 콘솔에만 남고 라벨러는 계속 작업하다 전부 잃었다. 경고는 지워지지
  않는 배지로, 복구는 자동 재시도로
- **추론 응답은 요청 시점 이미지에만 반영** — 단건 오토라벨·예시 매칭이 수 초
  걸리는 동안 `→`로 넘어가면, 늦게 온 응답이 지금 이미지의 라벨을 통째로
  교체하고 자동저장이 그걸 서버에 박았다. 이미지가 바뀌었으면 버리고 알린다
- **저장 완료가 dirty를 지우는 건 저장한 스냅샷이 최신일 때만** — 요청 비행
  중의 편집이 완료 순간 dirty와 함께 덮여, "저장됨"을 보고 닫은 탭에서
  마지막 편집이 사라졌다
- **공유 모델 상태는 set_image→predict를 원자화** — 배치 스레드와 `/embed`가
  전역 SAM predictor를 공유한다. torch가 GIL을 놓는 사이 끼어들면 A의 박스가
  B의 특징맵으로 디코딩되고, 오염된 임베딩이 해시 키로 캐시에 눌러앉는다
- **val/test 하한은 train 몫(절반)을 예약한 예산 안에서만** — 승인 8장에서
  하한 30이 전량을 val로 소진해 train 0장, 배정은 DB에 고착 — 이후 학습이
  영영 실패했다
- **삭제는 우리가 만든 파일만** — 연결 임포트 이미지의 실제 파일은 사용자
  원본이다. 이미지 삭제가 그걸 unlink해 도구 밖 데이터가 비가역 유실됐다
- **배치 오토라벨 기본 대상은 리뷰 전 이미지만** — 승인 이미지를 다시 돌리면
  검토된 라벨이 무검토 검출로 바뀌는데 status는 approved로 남아, 오염이
  학습셋까지 조용히 흘러갔다
- **온톨로지에 없는 클래스는 0번으로 오라벨하지 말고 제외 + 카운트** — 클래스
  이름 변경 후 익스포트가 옛 라벨을 전부 class 0으로 내보냈다
  (`X-Annotations-Skipped`)
- **부분 실패도 세서 알린다** — 업로드가 손상 파일을 조용히 건너뛰고 200을
  주면 프론트는 "N장 완료"로 거짓 보고한다. `saved`/`failed`를 함께 반환
- **대용량 응답을 RAM에 조립하지 않는다** — export.zip을 BytesIO에 만들면
  메모리가 데이터셋 크기만큼 치솟는다. 디스크 임시파일 + 전송 후 삭제,
  이미지 항목은 STORED (이미 압축본)
- **파생 상태는 원본에 동기화** — 온톨로지 에디터의 로컬 스냅샷이 밖에서 온
  갱신(임계값 적용·프롬프트 실험)을 모른 채 저장하면 그 변경을 조용히 되돌린다
- **유료 결과의 캐시는 "무엇이 판정됐나"를 키로** — VLM 판정 캐시는 기준 해시
  + 박스 스냅샷으로 잡고, 일시 장애(429·네트워크)는 error 플래그로 캐시에서
  제외한다. 안 그러면 장애 한 번이 영구 unsure로 굳고, 박스를 고쳐도 낡은
  판정이 유효한 척한다
- **백그라운드가 쓴 값은 전체 교체에서 보존 병합** — 판정(meta.vlm)은 서버가
  채우는데 클라이언트 사본에는 없다. 저장(DELETE+INSERT)이 그 사본을 그대로
  쓰면 유료 판정이 조용히 사라진다 — id 기준으로 보존 병합한다. 기록도
  통째 UPDATE 대신 json_patch로 키 하나만, 정체성(id+박스) 일치 조건과 함께
  (주의: json_patch는 RFC-7386 병합이라 이전 키 삭제는 명시적 null로)

## 한계

- 1인 로컬용 (SQLite, 인메모리 잡 상태) — 멀티유저는 큐/DB 교체 필요
- 라벨 타입은 bbox + 마스크 + 계층(part). OBB·비디오·OCR·3D 미지원
- 예시 찾기는 미세 결함(35px급)에서 무력 — 특징맵 해상도 한계, 파인튜닝 루프가 담당
- part 캐스케이드는 사람이 작게 찍히면 키포인트를 못 잡아 일반 경로로 폴백

- 전용 모델 YOLO 계열 = **AGPL-3.0** (개인/내부용 무방, 배포 시 RF-DETR 교체 지점 = `server/train_worker.py`)
