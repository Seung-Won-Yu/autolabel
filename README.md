# autolabel

**프롬프트 한 줄에서 전용 모델까지 — 로컬에서 돌아가는 오토라벨링 도구**

객체를 *말하거나 · 예시로 그리거나 · 클릭*하면 자동 라벨링하고,
승인 라벨이 쌓이면 **알아서 전용 모델을 학습**해 다음 라벨링부터 그 모델이 일한다.

클라우드 없음 · API 키 없음 · 데이터 유출 없음 — Apple Silicon 한 대로 전 과정 완결.

</div>

## 무엇이 다른가

기존 라벨링 도구는 "사람이 그리는 화면"이고, 오토라벨은 부가 기능이다.
이 도구는 반대로 **모델이 먼저 다 깔고, 사람은 틀린 것만 고치는 흐름**을 1급 시민으로 만들었다.

```
 ┌──────────────────────────────────────────────────────────────┐
 │  텍스트 프롬프트  ·  예시 박스 1개  ·  SAM 클릭              │
 └───────────────────────────┬──────────────────────────────────┘
                             ▼
                    자동 라벨 (배치/단건)
                             ▼
          리뷰 큐  ─ 불확실 우선 / 의심 우선 정렬
                             ▼
              승인 8장 → 전용 모델 자동 학습
                             ▼
        게이트 통과 시 오토라벨 엔진 교체 ──┐
                             ▲             │
                             └─────────────┘
                       라벨링할수록 라벨링이 쉬워진다
```

## 실측 성능

| 항목 | 수치 |
|---|---|
| 배치 오토라벨 (M4 Pro, MPS) | 장당 **0.8초**(박스) / 1.8초(박스+마스크) |
| SAM 클릭 보정 | 임베딩 1.4초/장(1회, 캐시) + 클릭당 **~120ms** (브라우저 실행) |
| 흔한 객체 제로샷 (person) | GT 기준 **mAP50 0.906** |
| **콜드스타트 구출** — PCB 결함, 제로샷이 완전 실패하는 도메인 | 제로샷 **≈0** → 승인 30장 **0.472** → 승인 42장 **0.593**<br>(홀드아웃 10장 고정 기준, 검출 3 → 43 → 64개 / GT 81개) |
| 예시 찾기 | 리모컨 1개를 예시로 → 나머지 전부 검출, 오탐 0 |
| champion/challenger 게이트 | 60장 challenger가 val 열세로 **승격 거부** — 나쁜 재학습 방어 실작동 |

> 핵심 결론: **흔한 객체는 첫날부터 자동, 특수 도메인은 수동 수십 장 투자 후 자동.**

## 기능

**라벨링**
- 텍스트 프롬프트 배치 오토라벨 (클래스별 프롬프트·임계값 분리)
- 예시 박스 1개 → 유사 객체 전부 (PerSAM 방식 특징 매칭, 학습 불필요)
- SAM 클릭 → 마스크 (클릭=새 객체, Shift=정제, 우클릭=제외)
- 박스 드래그·이동·리사이즈, 휠 줌 / Alt 팬

**리뷰**
- 썸네일 리스트 + 상태·라벨수·신뢰도·QA 점수
- 필터 4종 · **불확실 우선** · **의심 우선** 정렬
- `A`/`X` 승인·거부 후 자동 다음, `1~9` 클래스 재할당, `Cmd+Z` 실행 취소(50단계)
- 우측 어노테이션 패널 — 선택·클래스 변경·삭제, 출처 표시(🤖 모델 / ✍️ 사람 / ▦ 마스크)

**학습 & 품질**
- 승인 8장부터 자동 파인튜닝, 이후 5장마다 재학습 (별도 프로세스 — 서버 재시작에도 생존)
- 고정 골드 val 스냅샷 → 라운드 간 동일 기준 게이트
- 클래스별 추천 임계값 (정밀도 95% 달성 최소 confidence)
- 라벨 의심 랭킹 (모델 vs 라벨 불일치, 확신도 가중)
- COCO / YOLO 익스포트, 라벨 출처 메타데이터(모델명·프롬프트·임계값) 기록

## 스택

```
webapp/   Vite + React + react-konva
          └ SAM 디코더 ONNX(16.5MB)를 브라우저에서 실행 → 클릭당 서버비용 0

server/   FastAPI + SQLite
          ├ Grounding DINO   텍스트 → 박스
          ├ SAM ViT-L        박스 → 마스크, 임베딩, 예시 매칭
          ├ YOLO11n          전용 모델 (자동 파인튜닝, MPS)
          └ 엔진 라우팅       활성 전용 모델 우선, 없으면 파운데이션 폴백
```

## 실행

```bash
# 백엔드
.venv/bin/python -m uvicorn server.main:app --port 8899

# 프론트
cd webapp && npm run dev     # → http://localhost:5173
```

`models/sam_vit_l_0b3195.pth` 필요 ([SAM 공식 체크포인트](https://dl.fbaipublicfiles.com/segment_anything/sam_vit_l_0b3195.pth)).
Grounding DINO · YOLO11n은 첫 사용 시 자동 다운로드.

## 사용 흐름

1. 프로젝트 생성 → 클래스 정의 (이름 / 검출 프롬프트 / 임계값)
2. 이미지 업로드 → **전체 오토라벨**
3. 리뷰: `←→` 이동 · `A` 승인 · `X` 거부 · `Del` 삭제 · `?` 단축키
4. 보정: `B` 박스 · `M` SAM 클릭 · `E` 예시 찾기
5. 승인이 쌓이면 전용 모델이 자동 학습 → 오토라벨 품질 상승
6. `QA 분석` → 추천 임계값 확인 + "의심 우선"으로 라벨 오류 사냥
7. COCO / YOLO 익스포트

## 설계 원칙 (전부 실사고에서 나온 것)

- **마스크 원본 크기 복원은 브라우저 JS에서** — ONNX 그래프에 맡기면 세로 이미지에서 crop 치수가 뒤집힌다 (실측 IoU 0.18)
- **이미지 전환 시 임베딩 무효화** — 순번 검사 + 크기 검증으로 이전 이미지 임베딩 사용 레이스 차단
- **학습은 인프로세스 금지** — 서브프로세스 + 상태 파일. `--reload`가 학습 스레드를 죽인 사고에서 나온 규칙
- **champion/challenger + 품질 하한선(mAP50 ≥ 0.3)** — 재학습이 항상 개선은 아니다. 콜드스타트 쓰레기 모델의 승격 차단
- **온톨로지 = config** — 클래스명과 검출 프롬프트를 분리 (도메인 전환이 설정 변경으로 끝난다)

## 한계

- 1인 로컬용 (SQLite, 인메모리 잡 상태) — 멀티유저는 큐/DB 교체 필요
- 검출(bbox) + 세그멘테이션(마스크)만. 키포인트·OBB·비디오·OCR 미지원
- 예시 찾기는 미세 결함(35px급)에서 무력 — 특징맵 해상도 한계, 파인튜닝 루프가 담당
- 라벨 의심 랭킹은 모델이 약할 때 모델 오류가 섞인다 — "리뷰 가치 순"으로 읽을 것
- 전용 모델 YOLO11n = **AGPL-3.0** (개인/내부용 무방, 배포 시 RF-DETR 교체 지점 = `server/train_worker.py`)
